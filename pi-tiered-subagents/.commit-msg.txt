feat(pi-tiered-subagents): capture the parent's model as an owned identity

The durable snapshot used to hold the parent's live SDK model object,
carried through queues to child creation. Now it holds an owned
identity — provider and id, copied at capture — and the live object
stays in the session.

At assembly the identity is materialized through the session's model
bridge. That inverts the old invariant in the direction the
specification asks for: the identity is the durable fact the launch was
asked under, and the registry is only the materialization path. A model
the session no longer reports is an explicit failure — the run fails
with a named reason instead of silently starting the child on a
different model or dropping to an SDK default (story 42). The
prompt-inheritance strategy keys on the winning identity's provider, so
that decision needs no live object at all.

The launch's own resolved model still travels as the integration value
it always was — it won at preparation and is passed through unchanged;
the identity is only the fallback for launches the door resolved no
model for, and it materializes lazily, only when needed.

The model bridge itself (the narrow structural registry the child's
session creation uses to inherit providers) remains on the snapshot for
this increment; moving it behind a per-creation adapter is recorded as
remaining work rather than folded in silently.

Tests pin the seam: identity capture and copying, lazy materialization
through the bridge, explicit failure when the identity no longer
resolves (no session created), the launch's model still winning, and
the strategy keying on the identity's provider. 2,289 tests passing.
